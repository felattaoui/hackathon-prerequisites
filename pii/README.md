# PII in an agent runtime: teaching notebooks

How to handle personally identifiable information (PII) in an agent runtime: a LangGraph orchestrator
that receives requests over A2A and REST, calls an LLM, sub-agents, REST APIs and MCP tools, and keeps
memory and traces. One notebook per touchpoint, each built the same way:
**the request · what Azure offers (with Microsoft Learn links) · a demo · takeaways**.

Independent from `../hosted-agents/`. **Synthetic data only**: no real personal data is ever used,
stored or committed.

| Notebook | Touchpoint | Status |
|---|---|---|
| `00_setup` | Map of the touchpoints, vocabulary, Azure sign-in | ready |
| `01_inputs` | Detect PII in free text (5 languages), JSON payloads and images; travel identifiers; false positives | ready |
| `01b_presidio` | Same detection with Presidio: default settings vs configured (Azure Language plugged in) | ready |
| `02_llm_call` | Reversible pseudonymization around the LLM call; Foundry PII guardrail | planned |
| `03_agents_tools` | Minimization per sub-agent, API and MCP tool (in and out) | planned |
| `04_observability` | Traces and logs without PII before Application Insights | planned |
| `05_memory` | Short-term and long-term memory | planned |
| `06_knowledge_db` | PII at indexing time in a RAG index | planned |
| `07_audit` | Audit records with only legitimate PII | planned |

## Run

Python environment: the repository conda prefix `.conda/` (Python 3.13, with `azure-identity`, `httpx`,
`pillow`, `ipykernel`, `nbformat`, `nbclient`). Notebook `01b` also needs
`presidio-analyzer` and the spaCy models `en_core_web_md`, `fr_core_news_md`, `de_core_news_md`,
`es_core_news_md`, `xx_ent_wiki_sm` (`python -m spacy download <model>`).

```bash
az login                                   # Entra ID only: the lab resources have API keys disabled
bash pii/scripts/deploy.sh                 # creates the resource group and resources, writes pii/.env
.conda/python.exe pii/scripts/build_notebooks.py
# open pii/notebooks/*.ipynb in VS Code with the .conda kernel, or run headless:
.conda/python.exe pii/scripts/run_notebook.py pii/notebooks/01_inputs.ipynb
bash pii/scripts/teardown.sh               # deletes the resource group and purges the Foundry resource
```

Offline tests (rule-based detectors and repository hygiene): `cd pii && ../.conda/python.exe -m pytest`.

## Azure resources (step 1: notebooks 00 and 01)

Resource group from `config/lab.toml` (West Europe). One Foundry resource (`AIServices`, S0) used for
Azure Language PII detection and Document Intelligence Read: pay per use, no fixed cost. Local
authentication is disabled; the signed-in user gets the *Cognitive Services User* role.

## Layout

```
config/lab.toml              resource group and region (no secrets)
infra/main.bicep             lab resources
notebooks/pii_lab.py         helpers shared by the notebooks (Azure calls, rules, display, samples)
notebooks/NN_*.ipynb         generated by scripts/build_notebooks.py, versioned without outputs
scripts/                     deploy, teardown, build and run notebooks
tests/                       offline tests
```

Confidential source material stays in `inputs/` and is git-ignored. Executed notebooks go to
`results/` (git-ignored).
